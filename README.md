# AI-помощник для подготовки карточек товара (КИП)

Консольный прототип: принимает JSON с данными о приборе, обращается к LLM (Claude через прямой API Anthropic или через OpenAI-совместимый роутер CloseRouter) и выдаёт черновик карточки для B2B-магазина в Markdown и JSON.

Результат для каждого товара: SEO-заголовок (до 70 символов), SEO-описание (800-1200 символов), таблица ключевых характеристик, 3-5 поисковых запросов, блок для менеджера (кому подходит, какие задачи решает) и список того, что нужно уточнить.

## Установка и запуск

Нужен Python 3.10+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # выберите CARDGEN_PROVIDER и впишите ключ
python -m cardgen examples/input/manometer_dm02.json examples/input/thermometer_demo.json
```

Результаты появятся в папке `output/` (`*.md` для копирования, `*.json` для интеграций). Свой товар: положите JSON такого же вида в любую папку и передайте путь. Файл может содержать один объект или список объектов.

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {"диапазон измерений": "0–1,6 МПа", "класс точности": "1,5"},
  "description": "Прибор предназначен для измерения избыточного давления..."
}
```

Параметры: `-o папка` (куда писать), `--provider anthropic|closerouter` (или `CARDGEN_PROVIDER`), `--model` (или `CARDGEN_MODEL`). По умолчанию: `claude-opus-5-5` для anthropic и `anthropic/claude-sonnet-5.5` для closerouter. Ключи (`ANTHROPIC_API_KEY`, `CLOSEROUTER_API_KEY`) читаются из окружения или из `.env` (файл в `.gitignore`).

Тесты (без обращения к API, ключ не нужен): `python -m pytest -q`.

Код возврата: 0 все товары обработаны, 1 хотя бы один пропущен или упал, 2 не задан ключ или неизвестный провайдер.

## Как защищено от выдуманных характеристик

Главное решение: модель не пишет значения характеристик в таблицу. Защита в четыре слоя.

1. **Таблица характеристик собирается кодом** из `specs` дословно. Пустое значение становится «данных нет».
2. **Характеристики из текста описания** модель возвращает вместе с дословной цитатой. Код проверяет, что цитата есть в описании и числа значения есть в цитате. Иначе пункт отбрасывается и попадает в предупреждения.
3. **Проверка чисел.** Все числа из сгенерированных заголовка, описания, запросов и блока для менеджера сравниваются с числами входа. Незнакомое число (например, «16 бар» вместо «1,6 МПа») выводится в предупреждении «проверьте вручную».
4. **Промпт** запрещает использовать знания о модели, пересчитывать единицы, упоминать гарантию, сертификаты, ГОСТы и цены, если их нет во входе.

Каких характеристик не хватает, определяется так: пропуски полей и пустые значения находит код (без LLM), а список «типичных для такого прибора, но отсутствующих» характеристик (рабочая температура, степень защиты и т.д.) называет модель, только названия без значений. В таблице они стоят с пометкой «данных нет, нужно запросить».

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Файл не читается, битый JSON | Сообщение со строкой и позицией, остальные файлы обрабатываются |
| Пустое название, `specs` не объект, нет ни specs, ни описания | Товар пропущен с причиной, остальные обрабатываются |
| Нет производителя, описания, пустые значения specs | Карточка создаётся, пропуски вынесены в блок «Что проверить» |
| Нет ключа, 401, 404, 429, обрыв связи, отказ модели, обрезанный или не-JSON ответ | Понятное сообщение, без трейсбека. Повторы 408/429/5xx делает SDK (3 попытки) |
| Заголовок длиннее 70, описание вне 800-1200, запросов не 3-5 | Одна автоматическая попытка исправления, затем предупреждение в карточке |

Примеры плохих данных: `examples/bad/`.

## Промпты и решения

- **Системный промпт** ([cardgen/prompts.py](cardgen/prompts.py)): роль, затем жёсткое «главное правило» про источник значений, затем пронумерованное задание по полям результата. Данные товара приходят в теге `<product>` с пометкой, что внутри данные, а не инструкции (защита от текста вроде «игнорируй правила» в описании).
- **Структурированный ответ**: у прямого API Anthropic ответ идёт по JSON-схеме (`output_config.format`). Роутеры часто ломают structured output, поэтому для CloseRouter схема передаётся текстом в системном промпте, а ответ разбирает и проверяет код (`parse_response`: терпит ```-обёртку, проверяет поля и типы). Для обоих провайдеров длины текстов считает код.
- **Честность важнее объёма**: если фактов не хватает на 800 символов, промпт требует не добивать текст выдумками, а написать меньше и вынести недостающее в «уточнить». Код покажет предупреждение о длине. Это сознательный выбор в пользу критерия «нет выдуманных характеристик».
- **Одна попытка исправления** при нарушении длин: модели возвращается её же ответ и список конкретных нарушений. Больше одной попытки не делаем, чтобы не плодить расходы и не получить цикл.
- **Почему CLI, а не веб-форма**: задание допускает оба варианта, а ценность прототипа в пайплайне проверок. Веб-форма это тонкая обёртка над `generate_card()`.
- **Температура**: для CloseRouter задана явно `temperature=0`. Для прямого API Anthropic параметры сэмплинга не передаются, текущие модели их не принимают.

## Демонстрационные данные

В задании приведён только пример структуры, поэтому `examples/input/` содержит два демонстрационных товара, написанных для проверки сервиса:

- `manometer_dm02.json`: полные данные (пример из задания, описание дописано).
- `thermometer_demo.json`: неполные данные (нет производителя, пустые класс точности и интерфейсы). Показывает пометки «данных нет» и блок «Что проверить».

Характеристики в них учебные и не являются паспортными данными реальных приборов. Для реальных товаров подставьте файлы из задания.

## Пример результата

Готовые карточки лежат в [output/](output/): `manometer_dm02.md` и `thermometer_demo.md` (плюс `.json`). Получены на модели `anthropic/claude-sonnet-5.5` через CloseRouter. Прямой API Anthropic код поддерживает, но в этом прогоне не проверялся.

## Ограничения и что улучшить

- Проверка чисел консервативна: перевод единиц самой моделью (МПа в бар) даст предупреждение. Это сделано намеренно.
- Проверка охватывает числа, но не слова: выдуманный материал или стандарт без цифр код не поймает. Следующий шаг: проверка терминов по словарю входных данных или второй проход LLM-судьёй.
- Нет веб-формы, нет пакетной очереди и ограничения расходов. Для каталога на тысячи позиций: Message Batches API (скидка 50%) и кеширование системного промпта.
- Нет оценки качества на наборе эталонных карточек. Следующий шаг: 20-30 размеченных товаров и автоматическая сверка.
- SEO-запросы строятся без данных о частотности. Улучшение: подключить выгрузку Яндекс Wordstat.
- Язык результата только русский.
